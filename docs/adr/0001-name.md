# ADR-0001: Project name is "watoots"

**Date:** 2026-08-28  
**Status:** accepted

## Context

The scoping spec listed the name as an open decision: it needed a crates.io
name, a CLI verb, and a C prefix, and it needed to be settled before M1 to
avoid a rename. Three candidates were checked against crates.io, npm, PyPI,
GitHub, and Homebrew on 2026-08-28:

| Candidate | Result |
|---|---|
| `wazoo` | crates.io/npm free, but one letter from `wazero` (the Go wasm runtime that features in our own landscape), and `wazootech`/`wazoo.dev` is an existing dev-tooling company. |
| `wazzup` | crates.io **taken** by a Rust WASM project builder (v0.4.2, 2024); npm and PyPI taken; 234 GitHub repos; a commercial SaaS and a famous ad own the word. |
| `watoots` | Free everywhere: crates.io (`watoots`, `-host`, `-cli`), npm, PyPI, GitHub (zero repos, no user), Homebrew. Coined word; no `waz-` stem. |

## Decision

The project, primary crate, and CLI are named **watoots**.

- Crates: `watoots` (host library), `watoots-capi`, `watoots-trace`, `watoots-cli`.
- CLI binary: `watoots` (`watoots inspect`, `watoots run`, `watoots record`, `watoots replay`, `watoots trace fmt`).
- C prefix: `wt_` (e.g. `wt_host_t`, `wt_host_new`, `wt_plugin_call`). Wasmtime's C API uses `wasmtime_`/`wasm_`, so there is no clash. Headers: `watoots.h`, C++ wrapper `watoots.hpp`.
- Environment variables: `WATOOTS_*`.
- Repository directory: `~/development/watoots`.

## Consequences

- Search results and namespaces are ours from day one; no confusion tax with `wazero`.
- The name is playful; that matches the ecosystem (`wac`, `jco`, `wizer`) and is accepted.
- Reserving the crates.io names is deferred to the M1 session, once a real
  `Cargo.toml` exists, and is done under the maintainer's own account.
